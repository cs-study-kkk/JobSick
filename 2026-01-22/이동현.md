# DOM이란?

## DOM(Document Object Model)
DOM은 웹 문서의 구조화된 표현, HTML 요소를 자바스크립트 Object 처럼 조작할 수 있는 모델

<img width="880" height="453" alt="image" src="https://github.com/user-attachments/assets/d2c8e28f-8e02-4b9b-a630-c231bb21e593" />

프로그래밍 언어가 웹 페이지 내의 객체에 접근하고 조작할 수 있게 하는 인터페이스로 동작함

주로 자바스크립트에서 웹 페이지의 요소를 선택, 수정, 추가 또는 제거할 때 사용된다.

### 주요 특징 및 개념
1. DOM은 **트리 구조**로 표현되고, 각 노드는 웹 페이지의 다양한 부분을 나타낸다
2. DOM은 **라이브**라는 특성이 있음 --> DOM에 대한 변경은 즉시 웹 페이지에 반영이 됨
3. 자바 스크립트를 사용하여 DOM 요소를 선택, 수정, 추가 또는 제거할 수 있다.

### 주요 DOM 관련 메서드 및 속성
- 요소 선택
  - document.getElementbyID(id): 주어진 Id를 가진 요소를 반환

- 요소 조작
  - element.innerHTML: 요소 내부의 HTML을 가져오거나 설정
  - element.setAttribute(name, value): 요소의 속성값을 설정
  - element.getAttribute(name): 요소의 속성 값을 가져옴
- 이벤트 리스너
  - element.addEventListener(event, function): 요소에 이벤트 리스너를 추가
 
### 웹 페이지의 트리 구조
```
<body>
  <h1>안녕하세요.</h1>
  <ul>
    <li>
      리액트
    </li>
    <li>
      가상돔
    </li>
    <li>
      엘리먼트
    </li>

</body>
```

## CSSOM
CSSOM (CSS Object Model)은 DOM의 CSS 버전으로 생각

DOM은 HTML 문서의 구조화된 표현을 제공하는 것 처럼, CSSOM은 CSS 스타일 시트의 구조화된 표현을 제공

### 주요 특징 및 개념
1. CSSOM도 **트리 구조**로 구성됨 => 이 트리의 각 노드는 CSS 규칙을 나타내고, 이 규칙은 스타일 시트 내의 선택자, 속성 및 값에 해당
2. DOM과 마찬가지로 CSSOM 또한 **동적**이다. => 자바스크립트를 사용하여 실시간으로 CSSOM을 수정할 수 있고, 변경이 즉시 화면에 반영됨
3. **렌더링 블럭**: 웹 브라우저가 페이지를 렌더링할 때, CSSOM이 필수적

   why? 브라우저는 CSSOM과 DOM을 합쳐서 렌더 트리를 생성하고, 이 트리를 기반으로 페이지의 레이아웃 및 페인트를 수행하기 때문

   if CSSOM이 완전히 생성되지 않으면, 페이지의 렌더링이 차단될 수 있기에, CSS 자원의 로딩과 처리는 페이지의 성능에 큰 영향을 미칠 수 있음
4. **자바스크립트와의 상호작용**: 자바스크립트를 사용하여 CSSOM에 접근하고 변경이 가능함

### CSSOM의 최적화와 관련하여 기억해야 할 중요한 사항
1. **CSS 최소화 및 압축**: CSS 파일의 크기를 줄여 로딩시간을 최소화하기 위해
2. **비중요한 CSS 지연 로드**: 페이지 로딩의 초기 단계에서 필요하지 않은 CSS는 지연로드하거나 비동기적으로 로드하는 것이 좋음
3. **미디어 쿼리 활용**: 미디어 쿼리를 활용하여 특정 화면 크기 또는 장치 유형에만 적용되는 스타일 정의가 가능함

## 웹페이지 빌드 과정(CRP: Critical Rendering Path)

CRP: 웹 브라우저가 HTML, CSS, 및 JS와 같은 웹 페이지의 리소스를 받아서 실제로 화면에 페이지를 표시하는 과정을 의미함

=> 이 과정은 웹 페이지의 로딩 시간과 성능에 중요한 영향을 미치므로 최적화하는 것이 중요

### 주요 단계
1. DOM 트리 구축 (HTML 파싱 결과)
2. CSSOM 트리 구축 (CSS 파싱 결과)
3. 렌더 트리 구축 (DOM + CSSOM을 결합)
4. 레이아웃 (각 요소의 위치·크기 계산)
5. 페인팅 (픽셀로 화면에 그림)

<img width="1081" height="420" alt="image" src="https://github.com/user-attachments/assets/d25f506f-198d-47d6-af00-a1df75e9c8cc" />

=> HTML로 DOM을 만들고, CSS로 CSSOM을 만든 뒤 이를 결합해 Render Tree를 생성하고 Layout·Paint 과정을 거쳐 화면에 렌더링하는 전체 과정

### CRP 최적화 기법
CRP 최적화 목적: 가능한 한 빠르게 웹 페이지를 렌더링하게 하는 것

1. CSS와 JavaScript의 최소화 및 압축 (=> 파일 크기를 줄여 네트워크 전송 시간과 파싱 시간을 감소하기 위해)
2. 인라인 CSS와 Javascript의 사용 최소화 (=> 초기 렌더링 속도를 저하시킬 수 있기 때문)
3. 비동기 스크립트 로딩 (=> Javascript가 DOM 파싱을 막는 렌더링 차단을 방지하기 위해)
4. 중요한 CSS를 위쪽에 위치시키기 (=> CSSOM 생성 지연을 줄여 첫 화면을 빠르게 표시하기 위해)
5. 웹 폰트 최적화 (=> 폰트 다운로드로 텍스트 미표시 및 지연을 최소화하고 초기 렌더링을 빠르게 하기 위해)

## DOM/CSSOM이 트리 구조인 이유
1. HTML / CSS 자체가 **'계층적 언어'**이기 때문 
2. CSS의 핵심 개념 = 상속 => 트리 구조가 아니면 상속 계산이 매우 복잡해짐
3. 렌더링 파이프라인과 완벽하게 일치함
   - 렌더링 트리의 특징: 화면에 실제로 그릴 노드만 포함, 부모의 위치/크기가 자식에 영항을 줌
   - 그래서 레이아웃 계산은 부모 기준 -> 자식 기준으로 내려가야 함
   - 만약에 트리가 아니면 위치 계산, 크기 계산, overflow, flex, grid 전부 순서가 꼬임
4. 이벤트 전파 모델 => 부모-자식 관계가 명확해야 이벤트 흐름 정의 가능
   - 트리 구조가 아니면: “어디서 시작해서 어디로 퍼질지” 정의 불가
5. 그래서 왜 다른 구조는 안씀?
   - 리스트: 부모-자식 표현 불가능, 상속/이벤트 전파 불가함
   - 그래프: 스타일 상속 무한 루프의 위험이 있음, 렌더링 순서 결정이 어려움
   - 테이블/맵 구조: 문서 의미 표현이 불가, 레이아웃 계산에 부적합함
   - => 웹 문서 모델에는 단방향 계층 구조가 최적이라 트리 구조를 사용함

**결론**: DOM과 CSSOM은 HTML/CSS의 계층적 구조를 자연스럽게 표현하고, 스타일 상속, 렌더링 계산, 이벤트 전파를 효율적으로 처리하기 위해 트리 구조로 설계되었음
